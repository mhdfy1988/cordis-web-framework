## 1. 已确认与工程默认

用户已确认：独立框架项目，中性工程名 cordis-web-framework；FluidBlock 保留为后续应用。聚焦 Web，一套核心分别服务浏览器与服务端，不进入桌面和分布式治理。

本阶段采用的工程默认：先按职责建立最小模块，不预建完整多包工作区；在第一项可独立消费的核心出现时收口包导出、构建与依赖。正式品牌、注册表包名、发布渠道不在当前决定范围。

首版以可信进程内插件为基础；跨浏览器／服务端通过独立网络契约，不共享容器、用户身份对象或数据库连接。数据、身份协议与 HTTP 具体库后续查询评估，不视为已选定。

## 2. 职责与依赖

| 部分 | 拥有 | 不拥有 |
| --- | --- | --- |
| 公开契约 | 服务、插件、配置、版本、错误、状态和资源责任 | Cordis 私有类型、Vue、平台 API、业务表 |
| 公共核心 | 装配预检、配置协调、生命周期入口、基础日志契约与诊断 | Node／DOM 专属实现、第二套依赖引擎、产品逻辑 |
| Cordis 适配 | 固定库基线接入、状态映射、作用域桥接 | 对业务消费者暴露第三方内部对象 |
| 浏览器宿主 | 容器交接、浏览器能力、启动／卸载 | 服务器凭据、数据库连接、全部业务状态 |
| 服务端宿主 | 服务监听、进程退出、请求上下文与环境能力 | 产品算法、用户业务规则、固定管理后台 |
| 可选基础插件 | 呈现、HTTP、身份、存储、文件等完整公共能力 | 具体业务数据模型、隐藏的跨插件状态修改 |
| 业务插件 | 工作台、规则、业务修订、业务数据与提交条件 | 跨插件私有文件／DOM 操作、修改框架内部 |
| 装配组合 | 选择插件、提供者、配置、运行目标 | 复制业务实现、隐式服务竞争 |

依赖从应用经宿主／基础能力指向公开契约与核心，核心不反向依赖产品。服务路由注册、命令和界面位置各自有冲突／撤销规则，不用全局事件广播替代所有有返回值的服务调用。

## 3. 五类状态所有者

| 状态 | 所有者 | 退出责任 |
| --- | --- | --- |
| 装配、运行状态、基础诊断 | 应用运行实例 | 关闭本实例，不影响其他运行实例 |
| 服务登记、监听、订阅、计时和句柄 | 本轮插件作用域 | 停用时释放，不删除业务数据 |
| 请求身份、授权结果、取消与请求关联 | 本次请求上下文 | 请求结束释放，不写入插件全局单例 |
| 编辑草稿、选择与已确认业务修订 | 产品的编辑会话／业务服务 | 按产品规则保存或放弃，不由日志器接管 |
| 进度、并发、取消与结果状态 | 任务实例／任务服务 | 明确继续、排空或取消策略，迟到结果经业务确认 |

日志与界面可以观察投影，但不是另一份可写真值。缓存不替代业务存储。客户端取消等待不代表任务已停、事务回滚或已写入数据消失。

## 4. 启动和关闭的输入输出

启动输入：可信插件目录、装配文档、宿主类型、配置与来源信息。预检结构、身份、版本、配置、绑定、依赖与宿主要求之后，再创建运行实例；按真实必需能力就绪审计。

启动输出：可控制的应用实例、公开服务、只读状态与诊断。无效方案零激活；激活失败撤销本轮资源，保存故障证据。

关闭输入：明确的关闭意图和收尾策略。停止新业务 → 按策略处理请求／任务 → 消费者先于依赖资源退出 → 宿主收尾。输出须反映实际完成、清理失败或仍未释放；超时不能伪装干净关闭，也不能静默复用脏实例。

第 1 轮输入 A 启动任务；第 2 轮输入 B 使 A 失效，A 迟到不得覆盖 B；第 3 轮关闭视图释放订阅，后台任务是否继续由其契约决定。任务机制不替产品决定结果提交条件。

## 5. 首版初始验收范围

这是一条可逐步验证的初始主线，不把总体地图一次性安装完：

1. 无界面核心：可信装配、明确状态、资源生命周期、基础配置／日志与诊断，独立安装运行，不读来源项目私有源码。
2. 两种宿主：纯浏览器可独立构建；服务端可独立启动且不携带 Vue；配置／密钥与宿主专属依赖不串端。
3. 最小全栈样例：小型记录编辑，覆盖列表／修改、真实保存回读、参数错误、无权操作拒绝及日志关联。只作验收样例，不开发通用 CRUD 产品；真实认证提供者在相应选型阶段决定，测试身份夹具不得冒充生产登录。
4. 替换证明：至少两种同契约服务或布局实现，消费方不改；贡献撤销后监听与节点不残留。
5. 独立消费：第二个纯浏览器最小工具从框架产物使用公开入口，不依赖服务端或复制框架；FluidBlock 正式接入另行安排。

条件能力暂不作为核心前置：持久任务队列、实时推送、缓存、上传平台、完整账户管理、服务端渲染、桌面、多租户及微服务。真实验收路径需要时先收口语义再引入。

## 6. 验收与后续决策

W0 的完成只表示定位、边界、状态所有权、代表性闭环和来源审查已落盘；不表示库已选齐、核心已迁入或应用已可运行。

W1 开始前先收口框架包的独立构建与依赖方案：生产依赖、Cordis 补丁如何随安装生效、公开导出、浏览器／Node 类型目标及干净消费。依赖库必须有官方资料和实际包产物验证，不能只搬源码与通过类型检查。

W0 第一轮未升级 Cordis、移植产品界面、启动服务或直接引入整套技术栈。W1 后续加入配置／日志，W2 后续加入最小 HTTP 与浏览器宿主，相关事实各归所属阶段记录；身份、数据库与完整界面仍待后续阶段。
