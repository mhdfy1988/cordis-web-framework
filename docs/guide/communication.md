# 前后端通信与数据

浏览器服务对象不能序列化成服务端服务。两端分别装配插件，通过共有的 `JsonOperation<I, O>` 描述方法、路径、输入校验和输出校验。业务身份与仓储由应用实现，不放进通用核心。

## 运行最小通信例

在 kit 的 node 模板目录已安装依赖后：

```powershell
Copy-Item ../../docs/examples/http.mjs ./http.mjs
node ./http.mjs
```

成功判断：输出 `{ text: '来自浏览器的意图' }` 及服务器生成的请求 UUID，断言响应正确后关闭宿主，进程自然退出。该文件使用真实本地 HTTP，但不需要浏览器、数据库或账户。

处理流程：客户端先校验输入 → 发送协议／认证头与 JSON → 服务端限制请求并建立请求上下文 → 端点校验输入 → 应用处理 → 校验输出 → 严格响应信封 → 客户端验证请求标识、状态、结构和业务输出。

客户端请求的关键形式为 `client.request(operation, input, signal?)`，返回 `{ data, requestId }`，不是裸业务对象。`baseUrl` 是 HTTP(S) 源地址，不能带路径、查询、账号或 hash。GET 仅接收空对象，不把任意输入自动转查询参数。当前提供 GET／POST／PUT 的 JSON 协议，不宣称文件上传、流式传输或 WebSocket。

## 身份和权限

应用通过 `credential()` 提供当前凭据，客户端只会发送 Bearer 字段；服务端的 `context.credential` 仍是未认证输入，必须交由应用身份提供者验证，再检查资源权限。不能相信请求正文里的 `userId / role`，也不能把“当前用户”放在插件全局可写变量里。

框架请求上下文拥有 `requestId / signal / logger`，服务器生成请求标识。日志以标识关联，不记录凭据和业务正文。框架没有自动 OAuth、正式登录、跨域认证或多租户策略；跨源部署需要单独评估 CORS、令牌和安全，不通过 `mode: no-cors` 绕过。

## 保存、冲突和取消

记录模板提供的是应用样例：身份夹具→权限服务→SQLite 仓储。草稿留在浏览器会话；保存接收预期修订，冲突不能覆盖他人修改。

第 1 轮提交前取消：服务端在写入前检查信号，可以拒绝提交。

第 2 轮提交已完成、客户端才取消：数据库不会回滚，界面保持草稿并标记结果未确认；重新读取服务端结果后再决定下一次写入。

第 3 轮服务器退出：停止新接入，等待 HTTP 与实际处理器排空，再关闭数据库插件。客户端断开不等于处理器已经结束。

不要无条件自动重试写入；框架没有替所有业务提供幂等事务或撤销机制。替换存储时保留应用端口和事务语义，修改业务仓储适配，不改 JSON 客户端或 UI 核心。

## 错误和预算

请求、完整响应 UTF-8 预算为 65,536 字节，JSON 协议为字符串 `'1'`。客户端校验失败、网络错误、取消和服务端业务错误分别表达，见 [HTTP API](../reference/hosts-http.md)。服务端异常返回安全错误码，不回传异常栈。`ApiClientError.requestId` 可用于查询日志，不能因为有 HTTP 200 就跳过输出校验。
