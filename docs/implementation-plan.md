## N1—N8：npm 格式插件包支持计划

### 目标、复用与边界

目标是让遵守本框架接口的插件独立构建、独立交付，并能在运行中的宿主安装、启用、停用和卸载，不要求修改或重新构建主应用。可信代码仍在进程／页面内执行；依赖校验、内容摘要与安装脚本控制不能冒充沙箱。

保留现有管理核心对安装记录、启用意愿、运行状态、操作结果及恢复的单一所有权，复用 Cordis 调度和作用域清理；包来源、安装工具、文件存储、模块加载及资源提供放在平台适配边界。现有 .cwplugin.json 是有效的自包含插件包，不删除、不静默转换，也不因新来源失败回退旧路径。

区分三种依赖：包内相对模块由模块加载器处理；普通第三方代码依赖由构建或包管理器处理；跨插件服务依赖继续由框架声明、绑定和调度。Cordis／Vue 等宿主共享运行时不得被插件重复携带并产生第二套实例；具体外置与共享机制须在 N1／N2 证明。

### 状态与故障不变式

第一轮：宿主先启动，随后取得独立构建的 .tgz；安装阶段处理包及依赖并保存记录，不调用插件 setup。第二轮：明确启用后加载，依赖满足才进入就绪；失败保留安装事实、启用意愿和诊断，不把安装成功显示成运行成功。第三轮：停用等待真实清理，保留包和配置；刷新／重开按保存意愿恢复。第四轮：卸载先检查依赖并停止，再移除受管包及记录，默认不删除应用用户数据。

包文件系统变化与安装记录不构成天然原子事务。N1／N3 必须明确暂存、提交点、取消边界及中断恢复策略；不得假设回滚清单即可撤销安装脚本副作用。安装／卸载并发沿用统一协调，不在每个页面或加载器建立独立状态真值。

停用后的模块缓存不等于可强制清空；模块顶层不能持有未登记的实例资源。包管理器的磁盘卸载也不等于代码在引擎中被物理回收；不能承诺无限版本热替换或强杀可信进程内代码。
