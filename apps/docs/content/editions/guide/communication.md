# 前后端通信与数据

浏览器与服务端分别装配插件，通过共用的 JSON 操作契约通信，不序列化服务对象。身份、权限和仓储属于应用。

## 运行最小通信例

前置：在 kit 的 Node 模板目录完成锁安装。执行：

```powershell
Copy-Item ../../docs/examples/http.mjs ./http.mjs
node ./http.mjs
```

### 数据怎样流动

| 阶段 | 实际动作 |
| --- | --- |
| 客户端 | 校验输入，发送协议／认证头与 JSON |
| 服务端接入 | 限制请求大小，建立请求上下文 |
| 端点 | 校验输入，再调用应用处理器 |
| 应用 | 决定业务权限、副作用和提交边界 |
| 输出 | 校验业务结果，返回严格响应信封 |
| 客户端回读 | 核对请求标识、HTTP 状态、信封和业务输出 |

`JsonOperation<I, O>` 共同定义方法、路径和两端校验。调用形式为 `client.request(operation, input, signal?)`，返回 `{ data, requestId }`，不是裸业务对象。

`baseUrl` 只能是 HTTP(S) 源地址，不带路径、查询、账号或 hash。GET 只接受空对象，不把任意输入转成查询参数。当前支持 GET／POST／PUT 的 JSON 协议，不承诺文件上传、流式传输或 WebSocket。

## 身份和权限

- 客户端用 `credential()` 提供凭据，通过 Bearer 字段传输。
- 服务端的 `context.credential` 仍是未认证输入，应用先验证身份，再检查资源权限。
- 不相信请求正文中的 `userId/role`，不把当前用户写进插件全局变量。
- 请求上下文拥有服务器生成的 `requestId`、取消信号和日志器。用标识关联日志，不记录凭据或业务正文。

框架没有自动 OAuth、正式登录、跨源认证或多租户策略。跨源部署单独评估 CORS、令牌和安全，不使用 `mode: no-cors` 绕过协议校验。

## 保存、冲突和取消

记录模板的链路为“身份夹具 → 权限服务 → SQLite 仓储”，这是应用样例，不是框架内建账户系统。

草稿由浏览器会话保留。保存带预期修订，冲突不能覆盖他人修改。

| 时机 | 应有结果 |
| --- | --- |
| 第 1 轮：提交前取消 | 服务端写入前检查信号，可以拒绝提交 |
| 第 2 轮：提交完成后客户端取消 | 数据库不会回滚；保留草稿，标记结果未确认，重新读取后再决定下一次写入 |
| 第 3 轮：服务器退出 | 停止新接入，排空真实 HTTP 处理器，再关闭数据库插件 |

客户端断开不等于处理器已经结束。不要无条件重试写入；框架不替所有业务提供幂等事务或撤销机制。换存储时保留应用端口和事务语义，修改业务仓储适配，不改 JSON 客户端或 UI 核心。

## 错误和预算

| 项目 | 约束 |
| --- | --- |
| JSON 协议 | 字符串 `'1'` |
| 完整请求／响应预算 | UTF-8 `65,536` 字节，不是字符数 |
| 错误分类 | 输入校验、网络、取消、协议响应和业务错误分别表达 |
| 安全响应 | 只返回受控错误码，不回传异常栈 |

用 `ApiClientError.requestId` 查询脱敏日志，HTTP 200 不能替代输出校验。完整方法和状态码见 [HTTP API](../reference/hosts-http.md)。
